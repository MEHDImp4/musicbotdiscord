<objective>
Create .env.docker with Linux-compatible paths and update docker-compose.yml to use it, fixing the root cause of Docker startup failures.

Purpose: The bot currently fails in Docker because docker-compose.yml passes the host .env (containing Windows paths like C:\Users\mehdi\...\yt-dlp.exe) into a Linux container. This plan creates a separate .env.docker with portable values and rewires Compose to use it.

Output: .env.docker (new committable template), docker-compose.yml (env_file changed from .env to .env.docker)
</objective>

    - .env (existing host env — use ONLY for variable names, NOT values; contains Windows paths that must NOT appear in .env.docker)
    - src/config/env.ts (confirms which env vars the bot reads and their defaults)
  </read_first>
  <action>
Create `.env.docker` in the project root with:

1. Header comment: "Docker environment — Linux-compatible paths. Fill in your Discord credentials before running: docker compose up"
2. All variables from `.env.example` (same names, same defaults)
3. Placeholder values for secrets: `DISCORD_TOKEN=YOUR_DISCORD_TOKEN_HERE` and `DISCORD_CLIENT_ID=YOUR_CLIENT_ID_HERE`
4. Linux-compatible paths: `YTDLP_PATH=yt-dlp` and `FFMPEG_PATH=ffmpeg` (per ENV-01, ENV-02)
5. All other variables matching `.env.example` values exactly (LOG_LEVEL=info, IDLE_TIMEOUT_SECONDS=300, etc.)
6. Line endings MUST be LF (not CRLF) — this is critical for Docker on Linux. Use `\n` not `\r\n`.

Do NOT include any Windows paths (no `C:\Users\...`, no `.exe` extensions). The file must be safe to commit to git (placeholder secrets only, no real tokens).

Per D-01 (ENV-01) and D-02 (ENV-02): paths must be `yt-dlp` and `ffmpeg` — bare command names, no absolute paths.
  </action>
