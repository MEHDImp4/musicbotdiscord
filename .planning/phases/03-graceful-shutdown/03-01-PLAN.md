**Create src/shutdown.ts:**

This is a new self-contained module. Export a single `createShutdown` factory function that
accepts `{ client, players, logger }` and returns an async `shutdown(signal: string)` function.

The shutdown sequence must be:

1. **Guard against re-entry** — use a boolean `shuttingDown` flag. If already true, return immediately.

2. **Log the signal** — `logger.info({ signal }, "Shutting down")`.

3. **Start hard timeout** — `const hardTimeout = setTimeout(() => { logger.fatal("Hard timeout reached, forcing exit"); process.exit(1); }, 8_000);` — do NOT unref it so it keeps the event loop alive.

4. **Try/catch wrapper** — wrap steps 5-7 in try/catch. On catch, log the error and call `process.exit(1)`.

5. **Send disconnect messages (PROC-01)** — iterate `players.activeGuildIds`. For each guild ID:
   - `const guild = await client.guilds.fetch(guildId).catch(() => null)`
   - If guild is null, skip (guild unavailable).
   - Determine the target channel: first check if any player has `lastTextChannelId` set, otherwise fall back to `guild.systemChannel`.
   - If a channel is found, `await channel.send("ℹ️ Déconnexion du bot...").catch(err => logger.warn({ err, guild: guildId }, "Failed to send disconnect message"))`.
   - Use `Promise.allSettled` to send all messages concurrently so one failure does not block others.

6. **Destroy all players (PROC-02)** — `await players.destroyAll()`.

7. **Destroy client** — `await client.destroy()`. This closes the WebSocket connection cleanly
   so Discord marks the bot as offline immediately rather than after the heartbeat timeout (~45s).

8. **Clear hard timeout and exit** — `clearTimeout(hardTimeout); process.exit(0)`.

**Why a factory function:** The shutdown module needs `client` and `players` references but
should not hold them at module scope. A factory function creates a closure with these references,
making the module testable and avoiding circular imports.

**Why process.exit inside shutdown:** The current code already calls process.exit(0) after
shutdown. The hard timeout uses process.exit(1) to distinguish clean exit from forced exit.
The finally block in the SIGTERM/SIGINT handlers is removed since shutdown handles exit.

**Modify GuildPlayer.killProcesses() (src/music/GuildPlayer.ts, line 361-366):**

Replace the current synchronous implementation:
```typescript
private killProcesses(): void {
  for (const proc of this.childProcesses) {
    if (!proc.killed) proc.kill("SIGKILL");
  }
  this.childProcesses = [];
}
```

With an async implementation that returns `Promise<void>`:
```typescript
private async killProcesses(): Promise<void> {
  const processes = this.childProcesses;
  this.childProcesses = [];

  // Phase 1: Send SIGTERM to all processes
  for (const proc of processes) {
    if (!proc.killed) {
      proc.kill("SIGTERM");
    }
  }

  // Phase 2: Wait up to 1 second for graceful exit, then SIGKILL
  const SIGTERM_GRACE_MS = 1_000;
  await new Promise<void>((resolve) => {
    let resolved = false;
    const done = () => { if (!resolved) { resolved = true; resolve(); } };

    const killTimer = setTimeout(() => {
      for (const proc of processes) {
        if (!proc.killed) {
          proc.kill("SIGKILL");
          logger.warn({ pid: proc.pid }, "Force-killed process with SIGKILL after timeout");
        }
      }
      done();
    }, SIGTERM_GRACE_MS);

    // If all processes exit before timeout, clear the timer
    const checkAllExited = () => {
      if (processes.every((p) => p.exitCode !== null || p.killed)) {
        clearTimeout(killTimer);
        done();
      }
    };

    for (const proc of processes) {
      proc.on("exit", checkAllExited);
    }

    // Also check immediately in case processes are already dead
    checkAllExited();
  });

  logger.debug({ count: processes.length }, "All child processes terminated");
}
```

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Docker -> Node process | SIGTERM signal from Docker daemon; untrusted timing |
| Node process -> child processes | SIGTERM/SIGKILL signals to yt-dlp and FFmpeg; escalation must be controlled |
| Node process -> Discord API | channel.send() during shutdown; may fail if token is revoked |
| Shutdown -> process.exit | Hard timeout forces exit; must not leave corrupt state |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-01 | Elevation of Privilege | shutdown module | medium | mitigate | Idempotency guard prevents double-shutdown from triggering duplicate sends or double process.exit |
| T-03-02 | Denial of Service | channel.send during shutdown | low | accept | Failures are caught and logged; do not block the rest of shutdown |
| T-03-03 | Tampering | Child process signals | low | mitigate | SIGTERM grace period is fixed at 1s; SIGKILL is only sent to processes that did not exit; no user-controlled input affects the escalation logic |
| T-03-04 | Information Disclosure | Disconnect message content | low | accept | Message is a generic French string with no sensitive data |
| T-03-05 | Denial of Service | Hard timeout process.exit(1) | medium | mitigate | 8s timeout is below Docker's 15s stop_grace_period; process.exit(1) signals abnormal termination to Docker for restart policy |
</threat_model>
